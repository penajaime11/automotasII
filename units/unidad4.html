4.1

Registros

Los registros son la memoria más rápida del procesador. Una buena asignación de registros (register allocation) es crítica para el rendimiento final del código generado. El compilador debe decidir qué valores mantener en registros y cuáles dejar en memoria.

📊 Tipos de registros (x86-64)

RAX — acumulador / retorno
RBX — base (callee-saved)
RCX — contador / 4to arg
RDX — datos / 3er arg
RSI — 2do argumento
RDI — 1er argumento
RSP — stack pointer
RBP — base pointer (frame)

🔢 Asignación de Registros (Register Allocation)

Se modela como coloración de grafos: los nodos son variables, las aristas indican interferencia (uso simultáneo) y los colores son registros disponibles. Si dos variables interfieren no pueden compartir registro.

💾 Spilling

Cuando no hay suficientes registros, algunas variables se derraman (spill) a la memoria stack. Genera instrucciones LOAD/STORE adicionales que penalizan el rendimiento.

descriptor de registros y de direcciones
/* Descriptor de registro: qué variable tiene cada registro */
RegDesc[RAX] = {t1}
RegDesc[RBX] = {x, t2} // mismo valor, dos alias

/* Descriptor de dirección: dónde vive cada variable */
AddrDesc[t1] = {RAX}
AddrDesc[x] = {RBX, memoria[0x1020]}

/* getReg — elige el mejor registro para una instrucción */
function getReg(op, src1, src2, dst):
  if src1 ya está en registro y no se usa después → reusar
  else buscar registro libre → si no hay, hacer spill
4.2

Lenguaje Ensamblador

El lenguaje ensamblador es la representación simbólica del lenguaje máquina. Cada mnemónico corresponde exactamente a una instrucción del procesador. El compilador genera ensamblador, y luego el ensamblador (programa) lo convierte a binario.

traducción de código 3-dir → ensamblador x86-64
/* Código intermedio: t2 = a + b */
MOV RAX, [a] ; cargar a en RAX
ADD RAX, [b] ; RAX = RAX + b
MOV [t2], RAX ; guardar resultado en t2

/* Condicional: if x < y goto L */
MOV RAX, [x]
CMP RAX, [y] ; comparar x e y → flags
JL L ; Jump if Less → ir a L

/* Llamada a función f(arg1, arg2) */
MOV RDI, [arg1] ; 1er argumento
MOV RSI, [arg2] ; 2do argumento
CALL f
MOV [resultado], RAX ; retorno en RAX

📑 Estructura de un programa ensamblador

; Secciones típicas (NASM)
section .data ; datos inicializados
  msg db "Hola", 0

section .bss ; datos no inicializados
  buffer resb 64

section .text ; código ejecutable
  global _start
_start:
  ; instrucciones aquí

🔤 Instrucciones esenciales

  • MOV dst, src — copiar dato.
  • ADD / SUB — suma y resta.
  • MUL / DIV — multiplicación y división.
  • CMP — comparar dos operandos.
  • JMP / JE / JL / JG — saltos.
  • CALL / RET — llamada/retorno.
  • PUSH / POP — pila del sistema.
4.3

Lenguaje Máquina

El lenguaje máquina es la representación binaria final que ejecuta directamente el procesador sin ninguna traducción adicional. Cada instrucción codifica el opcode, los operandos y el modo de direccionamiento en patrones de bits.

🧩 Formato de instrucción tipo-R (MIPS 32 bits)

bits 31-26
opcode
6 bits
bits 25-21
rs
5 bits
bits 20-16
rt
5 bits
bits 15-11
rd
5 bits
bits 10-6
shamt
5 bits
bits 5-0
funct
6 bits

📡 Modos de direccionamiento

  • Inmediato: el operando es la constante. MOV RAX, 5
  • Directo: dirección de memoria explícita. MOV RAX, [100]
  • Indirecto: dirección está en registro. MOV RAX, [RBX]
  • Desplazamiento: base + offset. [RBP-8]
  • Indexado: base + índice × escala. [RBX+RCX*4]

⚙️ Proceso de ensamblado (2 pasadas)

  • 1ª pasada: recorre el código, construye tabla de símbolos y etiquetas con sus direcciones.
  • 2ª pasada: genera código binario resolviendo referencias usando la tabla del paso 1.
  • Produce archivo objeto (.o) con código reubicable.
  • Enlazador (linker): une módulos .o y resuelve referencias externas.
  • Resultado: ejecutable con direcciones absolutas listo para correr.
ejemplo: ADD en binario MIPS
/* ADD $t0, $t1, $t2 → $t0 = $t1 + $t2 */
/* opcode=0 rs=$t1(9) rt=$t2(10) rd=$t0(8) shamt=0 funct=0x20 */

000000 01001 01010 01000 00000 100000
  op rs rt rd shamt funct

Hexadecimal: 0x012A4020
4.4

Administración de Memoria

La administración de memoria define cómo y dónde se almacenan las variables, los registros de activación y los datos dinámicos durante la ejecución. El compilador genera código que gestiona estas tres regiones principales.

📌 Estática

Asignación en compile-time. Variables globales y estáticas. Dirección fija para toda la vida del programa.

static int contador = 0;
int global = 42;

📚 Stack (Pila)

Registros de activación para funciones. Se crean al llamar (push frame) y se destruyen al retornar (pop frame). LIFO automático, muy eficiente.

🌊 Heap (Montículo)

Memoria dinámica solicitada en run-time con malloc/free o new/delete. Flexible pero más lento; riesgo de fugas (memory leaks).
