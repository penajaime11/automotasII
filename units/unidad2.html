2.1

Notaciones

Las notaciones son formas de escribir expresiones según la posición del operador respecto a sus operandos. Son fundamentales para la generación de código intermedio.

2.1.1 Prefija

El operador va antes que sus operandos. También llamada notación polaca.

-- a + b * c --
+ a * b c

2.1.2 Infija

El operador va entre los operandos. Es la notación matemática estándar.

-- expresión normal --
a + b * c

2.1.3 Postfija

El operador va después de los operandos. Notación polaca inversa (RPN).

-- a + b * c --
a b c * +
conversión infija → postfija con pila
/* Algoritmo shunting-yard (Dijkstra) */
for each token in expresión_infija:
  if token es operando → agregar a salida
  if token es ( → push a pila
  if token es ) → pop pila hasta (, agregar a salida
  if token es operador → pop mientras precedencia mayor, luego push
while pila no vacía → pop y agregar a salida
2.2

Representaciones de Código Intermedio

El código intermedio es una representación interna del programa que es independiente de la arquitectura objetivo, facilitando la portabilidad y la optimización.

2.2.1 Notación Polaca (Inversa — RPN)

Los operadores siguen a sus operandos. Se evalúa con una pila: al encontrar un operador, se sacan los operandos necesarios, se opera y se empuja el resultado.

-- Expresión: (3 + 4) * 5 --
3 4 + 5 *

-- Evaluación con pila --
push 3 → [3]
push 4 → [3, 4]
+ → pop 4, pop 3, push 7 → [7]
push 5 → [7, 5]
* → pop 5, pop 7, push 35 → [35]

2.2.2 Código P (P-code)

Código para una máquina de pila abstracta. Fue popularizado por Pascal. Las instrucciones operan sobre una pila de datos virtual.

ejemplo: a := b + c * d
lod b // carga b
lod c // carga c
lod d // carga d
mpi // multiplica c * d
adi // suma b + (c*d)
str a // almacena en a

2.2.3 Triples

Cada instrucción tiene la forma (operador, arg1, arg2). Los resultados se referencian por el número de la instrucción que los generó (implícito).

#OperadorArg1Arg2
(0)*cd
(1)+b(0)
(2):=a(1)

⚠️ Problema: difíciles de reordenar durante optimización (referencias implícitas).

2.2.4 Cuádruplos

Forma (operador, arg1, arg2, resultado). El resultado es explícito mediante temporales. Facilitan la optimización y reordenamiento.

#OpArg1Arg2Resultado
0*cdt1
1+bt1t2
2:=t2—a

✅ Más flexibles que triples. Son la representación más usada en compiladores modernos.

2.3

Esquema de Generación

El esquema de generación define cómo traducir cada construcción del lenguaje fuente a código intermedio de 3 direcciones.

2.3.1–2.3.3 Variables, expresiones y asignaciones
/* Variables y constantes */
E → id action: { E.lugar = tabla[id] }
E → num action: { E.lugar = num.val }

/* Expresiones aritméticas */
E → E₁ + E₂ action: { t=nuevo(); emit(t ":=" E₁ "+" E₂); E.lugar=t }

/* Asignación */
S → id := E action: { emit(id ":=" E.lugar) }
2.3.4 Instrucciones de control — if/while
/* IF-THEN-ELSE */
S → if E then S₁ else S₂:
  generar: ifFalse E.lugar goto Lfalso
  código de S₁
  goto Lfin
  Lfalso: código de S₂
  Lfin:

/* WHILE */
S → while E do S₁:
  Linicio: evaluar E
  ifFalse E.lugar goto Lfin
  código de S₁
  goto Linicio
  Lfin:
2.3.5 Funciones
/* Llamada a función */
for each arg in args:
  emit("param" arg)
emit("call" f, n)
emit("result" t)

/* Retorno */
emit("return" E.lugar)
2.3.6 Estructuras / Arreglos
/* Acceso a arreglo a[i] */
t1 = i * ancho_elem
t2 = base_a + t1
t3 = *t2 // indirección

/* Asignación a[i] := x */
t1 = i * ancho_elem
t2 = base_a + t1
*t2 = x
