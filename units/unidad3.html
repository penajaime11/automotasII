3.1

Tipos de Optimización

Optimización local actúa dentro de un bloque básico: secuencia lineal de instrucciones sin saltos. Es el tipo más seguro y fácil de aplicar.

antes de optimizar
t1 = a + b
t2 = a + b // subexp. repetida
t3 = 2 * 3 // constantes
t4 = t1 + t3
x = t4
y = t4 // propagación
después de optimizar
t1 = a + b // una sola vez
// t2 eliminado (= t1)
// t3 = 6 (plegado)
t4 = t1 + 6 // constante incrustada
x = t4
y = t4 // copia propagada

🔎 Técnicas locales principales

  • Eliminación de subexpresiones comunes (CSE).
  • Plegado de constantes (Constant Folding): evaluar en compile-time.
  • Propagación de copias: reemplazar t2=t1 usando t1 directamente.
  • Eliminación de código muerto: código que no afecta la salida.

Optimización de ciclos es donde más se gana en rendimiento, ya que el código se ejecuta repetidamente.

🔄 Técnicas para ciclos

  • Movimiento de código invariante: sacar instrucciones que no cambian del cuerpo del ciclo.
  • Reducción de intensidad: reemplazar operaciones costosas por equivalentes más baratas (ej. multiplicación → suma).
  • Eliminación de variables de inducción: si i y j=4*i evolucionan juntas, eliminar cálculos redundantes de j.
  • Desenrollado de ciclos (Loop Unrolling): duplicar el cuerpo para reducir saltos.
movimiento de código invariante
/* Antes */
while (i < n) {
  t = base + w; // invariante! (no cambia)
  a[i] = t * i;
  i++;
}

/* Después */
t = base + w; // movido fuera del ciclo
while (i < n) { a[i] = t * i; i++; }

Optimización global analiza el flujo de datos a través de todos los bloques básicos del programa usando grafos de flujo de control.

🌐 Propagación global

Propagar valores constantes y copias más allá de los límites de un bloque básico, incluso a través de bifurcaciones.

💀 Código muerto global

Variables que son definidas pero nunca usadas en ningún camino del grafo de flujo se pueden eliminar.

La optimización de mirilla (peephole) examina una pequeña ventana de instrucciones contiguas en el código objeto y las reemplaza por secuencias equivalentes más cortas o rápidas.

ejemplos de optimización de mirilla
/* Salto redundante */
goto L1 // Antes
L1:
→ L1: // Después (eliminar goto)

/* Store-load redundante */
ST R0, x // guarda R0 en x
LD R0, x // vuelve a cargar x en R0
→ ST R0, x // segunda instrucción es redundante

/* Multiplicación por potencia de 2 */
t = x * 2 → t = x << 1 // shift izquierda
3.2

Costos

La optimización implica evaluar el costo de ejecución para decidir cuándo una transformación es beneficiosa sin aumentar el tiempo de compilación excesivamente.

3.2.1 Costo de Ejecución

Ciclos de CPU, accesos a memoria, uso de registros y pilas. Las operaciones de memoria son mucho más costosas que las de registro.

3.2.2 Criterios de Mejora

Reducir instrucciones, reemplazar operaciones lentas por rápidas, minimizar accesos a memoria y aprovechar el caché.

3.2.3 Análisis de Flujo de Datos

Calcular conjuntos GEN, KILL, IN, OUT para cada bloque básico usando ecuaciones de punto fijo.

análisis de flujo — definiciones disponibles
/* Para cada bloque B */
GEN[B] = definiciones generadas en B no eliminadas después
KILL[B] = definiciones de otros bloques eliminadas por B

IN[B] = ∪ OUT[P] para todo predecesor P de B
OUT[B] = GEN[B] ∪ (IN[B] − KILL[B])
