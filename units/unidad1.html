1.1

Árboles de Expresiones

Un árbol de expresión es un árbol binario donde las hojas son operandos y los nodos internos son operadores. Es la representación interna más natural de una expresión dentro de un compilador.

Expresión: (a + b) * (c − 3)

*
+
a
b
−
c
3

🌳 Tipos de recorrido

  • Preorden: Operador → Izq → Der → * + a b − c 3
  • Inorden: Izq → Op → Der → a+b * c−3
  • Postorden: Izq → Der → Op → a b + c 3 − *
1.2

Acciones Semánticas del Analizador Sintáctico

Las acciones semánticas son fragmentos de código embebidos en la gramática que se ejecutan durante el reconocimiento sintáctico para construir estructuras de datos y verificar restricciones de contexto.

⬆️ Atributos Sintetizados

Se calculan de abajo hacia arriba. El valor del padre depende de los hijos. Son el caso más común en parsers LALR.

E → E + T { E.val = E.val + T.val }
E → T { E.val = T.val }

⬇️ Atributos Heredados

Se pasan de arriba hacia abajo. El padre transmite información a los hijos. Comunes para verificar tipos y ámbitos.

D → T L { L.tipo = T.tipo }
L → id { insertar(id, L.tipo) }
calculadora con gramática dirigida por sintaxis (SDD)
/* Cada producción incluye su acción semántica */
E → E₁ + T action: { E.val = E₁.val + T.val }
E → E₁ - T action: { E.val = E₁.val - T.val }
E → T action: { E.val = T.val }
T → T₁ * F action: { T.val = T₁.val * F.val }
T → F action: { T.val = F.val }
F → (E) action: { F.val = E.val }
F → num action: { F.val = num.lexval }
1.3

Comprobaciones de Tipos en Expresiones

El verificador de tipos garantiza que las operaciones se apliquen a operandos compatibles. Opera en tiempo de compilación (estático) o en tiempo de ejecución (dinámico).

🔒 Tipado Estático

Verificación antes de ejecutar. Detecta errores temprano. Ej: C, Java, Pascal.

🌊 Tipado Dinámico

Verificación en ejecución. Mayor flexibilidad. Ej: Python, JavaScript, Ruby.

reglas de compatibilidad de tipos
function checkType(E):
  case E = E₁ + E₂:
    if (E₁.type == INT && E₂.type == INT) return INT
    else if (E₁.type == FLOAT || E₂.type == FLOAT) return FLOAT // coerción
    else errorTipo("Tipos incompatibles en +")

🔄 Coerciones y Conversiones

Implícita (coerción): El compilador convierte automáticamente.
float f = i + 2.0;

Explícita (cast): El programador fuerza la conversión.
float f = (float) i;

1.4

Pila Semántica en el Analizador Sintáctico

En los parsers LR/LALR, la pila semántica es un espejo de la pila de estados que almacena los atributos de los símbolos. Al reducir, los atributos del cuerpo se combinan para calcular el atributo de la cabeza.

Parseando: 3 + 4 * 2

ESTADOS

s0
s2 (3)
s5 (+)
s2 (4)
s7 (*)
s2 (2) ←

SEMÁNTICA

—
val=3
—
val=4
—
val=2 ←

📌 Operaciones sobre la pila

  • Al hacer shift: se empuja el lexval del token.
  • Al hacer reduce: se sacan n atributos del cuerpo.
  • Se calcula el atributo sintetizado con la acción.
  • Se empuja el nuevo atributo calculado.
-- Reducción: E → E + T --
T.val = pop() // saca T
         pop() // descarta '+'
E₁.val = pop() // saca E₁
push(E₁.val + T.val)
1.5

Esquema de Traducción

Un Esquema de Traducción Dirigido por Sintaxis (STDS) es una gramática libre de contexto donde las producciones incluyen acciones incrustadas indicando cuándo ejecutarlas.

esquema de traducción — infija a postfija
E → E₁ + T { print("+") }
E → T
T → T₁ * F { print("*") }
T → F
F → (E)
F → num { print(num.val) }

/* Entrada: 3+4*2 → Salida: 3 4 2 * + */

⬆️ S-atribuidas

Solo atributos sintetizados. Acciones al final de las producciones. Compatibles con LR.

↕️ L-atribuidas

Sintetizados y heredados. Heredados solo de padres o hermanos izquierdos. Compatibles con LL.

💡 Ejemplo: Traducción a código de 3 direcciones

S → id := E→{ gen(id.lugar ':=' E.lugar) }
E → E₁ + E₂→{ t=nuevaTemp(); gen(t ':=' E₁ '+' E₂); E.lugar=t }
E → -E₁→{ t=nuevaTemp(); gen(t ':=' 'uminus' E₁); E.lugar=t }
E → id→{ E.lugar = id.lugar }

Tabla de Símbolos y Tabla de Direcciones

La tabla de símbolos es la estructura de datos central del compilador. Registra información de cada identificador y se consulta en todas las fases de la compilación.

🔧 Implementaciones

  • Lista enlazada — O(n) búsqueda.
  • Árbol binario de búsqueda — O(log n).
  • Tabla hash — O(1) promedio. La más usada.
  • Hash con encadenamiento para ámbitos anidados.

📍 Tabla de Direcciones

Asigna a cada variable una dirección relativa dentro de su registro de activación.

x: base + 0
y: base + 4
z: base + 8

1.7

Manejo de Errores Semánticos

Los errores semánticos son errores de significado: el programa es sintácticamente correcto pero tiene incoherencias. El analizador debe detectar, reportar y recuperarse sin detener la compilación.

❌ Error de Tipo

Operación entre tipos incompatibles.
int x = "hola";

⚠️ No Declarada

Uso de identificador no registrado.
y = x + z; // z no declarada

🔍 Error de Ámbito

Acceso a variable fuera de su alcance.

⚡ Aridad Incorrecta

Número de argumentos incorrecto.
suma(1,2,3) // espera 2

estrategia de recuperación — propagación de error
if (error_tipo) {
  reportar("Error semántico línea " + linea);
  E.tipo = ERROR; // propagar para evitar cascada de falsos errores
}
if (E₁.tipo == ERROR || E₂.tipo == ERROR)
  E.tipo = ERROR; // sin reporte adicional
